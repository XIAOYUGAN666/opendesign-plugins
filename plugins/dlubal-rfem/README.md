# RFEM plugin development source

`plugin.json` is the sole human-maintained plugin identity. This development root contains the independent [RFEM Connector](connector/README.md), its frozen dependency inputs, tests and build tooling, plus the standard [workflow skill](skills/rfem-workflow/SKILL.md). Migration provenance is recorded in [ORIGIN.md](connector/ORIGIN.md). This repository is the sole connector source owner; the duplicate main-repository connector has been retired. A development checkout is separate from an installed signed artifact.

The common repository builder stages a self-contained Windows artifact from these sources. It includes the root manifest, runtime, generated configuration/startup/lifecycle schemas, actual standard MCP declarations, inventory, SBOM and risk evidence. The typed configuration source owns the safe display annotations and required Dlubal secret declaration. The native extension requires the compatible Windows Host; other Agent Plugins clients can consume only their supported standard components, without a claim of portable engineering execution.

Managed startup uses connector bootstrap v3 over the Host-owned bounded stdin/stdout control pipe. The Host starts one connection coordinator for each active connector; it sends the same typed `EnsureSoftwareConnection` command on startup, on the 120-second healthy interval, after transient backoff, or after the user clicks “Reconnect”. The connector does not run a second retry loop. Metadata mode discovers all eight tool declarations without a business key or RFEM and rejects engineering calls. The signed tool preview is only for configuring tools and never establishes an engineering connection. Execution mode requires the Host-managed key, exact RFEM build and controlled state directory. No environment, INI, model-message or workspace-file fallback is introduced for business credentials. Credential storage, installation and process lifecycle remain Host responsibilities.

The target is RFEM `6.14.0013.249` through `dlubal.api==2.14.13`. Software connection confirmation uses only Dlubal `Service.get_application_info` and `Service.close_connection`; the adapter never calls Core, model, calculation, result, script, or export methods. Saving a key does not confirm the software connection. Missing/invalid credentials, an absent RFEM process, and unsupported builds return a fixed reason and pause automatic checks until an explicit reconnect. Connector errors and unresolved synchronous work remain explicit; unknown engineering writes must not be repeated automatically. Deterministic tests and unsigned development artifacts do not establish live software or engineering-result acceptance.

RFEM 0.1.1 and Marketplace sequence 1 were explicitly approved and published on 2026-10-20 after public asset and production Host verification. `published/` and formal Stable discovery are generated only from those approved immutable release inputs. Later development source changes do not update that view. Every future public Stable Release and Marketplace update still requires final publisher confirmation.
