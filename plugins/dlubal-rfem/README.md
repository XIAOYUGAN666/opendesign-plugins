# RFEM plugin development source

`plugin.json` is the sole human-maintained plugin identity. This development root contains the independent [RFEM Provider](provider/README.md), its frozen dependency inputs, tests and build tooling, plus the standard [workflow skill](skills/rfem-workflow/SKILL.md). Migration provenance is recorded in [ORIGIN.md](provider/ORIGIN.md). This repository is the sole Provider source owner; the duplicate main-repository Provider has been retired. A development checkout is separate from an installed signed artifact.

The common repository builder stages a self-contained Windows artifact from these sources. It includes the root manifest, runtime, generated configuration/startup/lifecycle schemas, actual standard MCP declarations, inventory, SBOM and risk evidence. The typed configuration source owns the safe display annotations and required Dlubal secret declaration. The native extension requires the compatible Windows Host; other Agent Plugins clients can consume only their supported standard components, without a claim of portable engineering execution.

Managed startup uses envelope 2 through anonymous stdin. Metadata mode discovers all eight tool declarations without a business key or RFEM and rejects engineering calls. Normal disconnected UI uses the signed tool preview; preview availability never establishes an engineering connection. Execution mode requires the Host-managed key, exact RFEM build and controlled state directory. No environment, INI, model-message or workspace-file fallback is introduced for business credentials. Credential storage, installation and process lifecycle remain Host responsibilities.

The target is RFEM `6.14.0013.249` through `dlubal.api==2.14.13`. Saving a key, read-only authentication/build verification and engineering execution are distinct operations. Provider errors and unresolved synchronous work remain explicit; unknown engineering writes must not be repeated automatically. Deterministic tests and unsigned development artifacts do not establish live software or engineering-result acceptance.

RFEM 0.1.1 and Marketplace sequence 1 were explicitly approved and published on 2026-10-20 after public asset and production Host verification. `published/` and formal Stable discovery are generated only from those approved immutable release inputs. Later development source changes do not update that view. Every future public Stable Release and Marketplace update still requires final publisher confirmation.
