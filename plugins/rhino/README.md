# Rhino plugin development source

`plugin.json` is the sole human-maintained plugin identity. This root contains the independent [Provider](provider/README.md), its project and lock, [native Bridge](native/), typed contracts and the static [workflow Skill](skills/rhino-workflow/SKILL.md). This repository is the sole Provider and Bridge source owner; the duplicate main-repository source has been retired. A development checkout is separate from an installed signed artifact.

The common builder stages `runtime/python/python.exe` with `rhino_mcp` under its isolated site-packages and packages the actual dual-target Bridge Yak. Native inventory and archive hashes are generated from real frozen build inputs and checked against both assemblies, never placeholders. Provider configuration, lifecycle schemas and MCP preview are generated from Provider-owned declarations.

Startup envelope 2 is implemented by the migrated Provider. Controlled metadata mode lists 70 tools, one resource plus three templates and two prompts without a Bridge connection, and rejects all tool calls. Actual execution requires a compatible authenticated native lease. MCP resource generation/bearer and Bridge lease generation/token have separate owners; only a real still-live authenticated lease may be reused after prior work safely settles. Unknown dispatch is sticky and cannot be cleared by reconnecting or restarting the Provider.

Native callback closure is an explicit per-handler property, independent of read-only status or operation success. Source audit and lifecycle tests cover 35 explicitly classified synchronous handlers, including command listing, selected-object inspection, geometry analysis and ordinary geometry/document operations. This proves return of the Bridge-owned callback, not successful engineering postconditions or completion of arbitrary third-party event effects. Scripts, general commands and Grasshopper retain conservative unknown handling. Geometry analysis reports curve/mesh closure only for those geometry types and Brep solidity for Breps; absent metrics are not false measurements. These source changes require a newly built candidate and separate native acceptance; an already loaded Bridge is not updated by compiling source.

Engineering tools require the compatible Windows Host and Rhino 8 build `8.26.25349.19001`. Configuration and Skills grant no execution authority. Common Host integration and live engineering postconditions remain separate acceptance gates. Other Agent Plugins clients can load only standard components they support; portable native engineering execution is not claimed.

The release SDK is selected by [global.json](global.json) without roll-forward. Native release inputs include that file and the project properties disabling implicit Source Link and source-control queries. The opt-in reproducibility test builds the actual native source in an isolated Git fixture, changes only its noncompiled checkout context, and compares both target payloads; the main repositories and their branches are untouched. This is build evidence and grants no live engineering or Stable approval.

The release helper fixes `DOTNET_CLI_UI_LANGUAGE=en-US` in its child processes only: MSBuild-generated source contains localized text, so an unspecified caller culture changes native bytes. The actual two-language build regression compares both target payloads under `zh-CN` and `en-US`; operating-system language and global environment settings are not changed. See the [official MSBuild language behavior](https://learn.microsoft.com/en-us/dotnet/core/compatibility/sdk/8.0/msbuild-language). Failed builds report only fixed phase categories, never subprocess commands or output; a native binding mismatch still rejects the candidate.

Local component checks and reproducible unsigned development candidates do not establish real Rhino acceptance or publication. Rhino 0.1.15 and Marketplace sequence 1 were explicitly approved and published on 2026-10-20 after public asset and production Host verification; engineering postconditions are recorded separately by the main application's T33/T34 acceptance. `published/` and formal Marketplace discovery contain approved immutable Stable inputs, independently of current development source. Future public Stable Release and Marketplace updates still require publisher confirmation.
