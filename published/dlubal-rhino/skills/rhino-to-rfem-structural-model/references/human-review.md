# Human review

Use existing valid confirmation and tool permission records. Engineering confirmation means confirmation of the concrete conversion proposal, not a third approval in addition to that proposal confirmation. On resume, continue from verified completed stages; request a new decision only for relevant changes or unresolved essential inputs. Missing section data blocks the affected mapping or engineering write, not the inventory or extraction of other justified axes.

Provide a reviewable, versioned proposal with: source scope and every object disposition; units, coordinates, tolerances and axis changes; member classifications and material/section/local-axis mappings; connectivity, offsets, releases, supports and required initial conditions; intended target and stages; and all unresolved conflicts. Explain differing source-object and analysis-member counts.

Group genuinely equivalent objects for review and permit individual overrides. Do not assign the same connection merely because objects share a layer. If a Rhino preview is useful, create only authorized preview objects and preserve source geometry; without modification permission use a textual review.

Wait for the user to explicitly confirm the complete specific proposal before any RFEM mutation. A tool approval, an incomplete classification confirmation or silence is not that confirmation. Changes to source geometry, instance transforms, attributes, scope, tolerances, mapping or target invalidate affected confirmation even when GUIDs are unchanged. Show the changed objects and obtain confirmation again. If essential inputs remain unresolved, report a partial or explicitly authorized non-calculation geometry draft, never a complete engineering model.
