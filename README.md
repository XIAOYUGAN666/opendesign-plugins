# OpenDesign plugin sources

[`dlubal-rhino`](plugins/dlubal-rhino/README.md) is a development-source pure skill package for guiding Rhino-to-RFEM structural modelling. It uses the separately managed Rhino and RFEM connectors; a development source is not an installed or published package.

This repository contains Dlubal RFEM and Rhino connector development roots and pure skill package sources in `plugins/`. Each root Manifest is the only human source of plugin identity. Development versions do not themselves announce a new Stable release or provide installable assets.

RFEM and Rhino now have independent Connector projects, locks, tests and static workflow Skills under their development roots. Rhino also owns its native Bridge and contracts. Root scripts and tests use the Python 3.12 standard library; dependency-sensitive verification runs in an explicitly selected, independently frozen project. There is no root Python project or environment.

```powershell
python -B -m unittest discover -s tests -p test_contract_import.py -v
```

Import public exported contracts with `python -B scripts/import_contracts.py <host-native-owner> <agent-owner> schemas --host-contract-schema <v3-owner> --configuration-schema <configuration-owner> --official-schema <official-1.0.0-copy>`. Inputs are explicit exported files; no runtime import is required. The original three positional arguments also work. The importer copies original bytes and generates `schemas/owner-contracts.json` with owner references, versions and fresh SHA-256 digests. Fixed schema copies use `-text` checkout attributes.

The native namespace `io.github.xiaoyugan666.native` is a Windows Host extension, not an Agent Plugins standard component. Declared entrypoints are paths inside signed Windows installation ZIPs, not source-tree executables. These roots have no fake `mcp.json` endpoint. Both connectors use the same startup v3 and bounded bidirectional control contract; no older connection protocol is started. Host integration and live engineering acceptance remain separate gates; schema acceptance alone establishes neither. Rhino receives authenticated native peer changes over the same Host-owned control pipe used by its connector; MCP resource generation and Bridge lease generation retain their distinct owners.

A required API Key belongs to engineering connection readiness. Installing a plugin package does not require the user's key. Non-native clients can load only standard components they support; engineering tools require a compatible Windows Host, real software and any required credentials. Skills and configurations grant no execution permission. Signed workflow Skills are static guidance, not executable authority. Missing RFEM credentials or an authenticated Rhino Bridge blocks engineering calls; build-only metadata mode cannot bypass those gates.

`published/` contains automatically generated views from approved immutable Stable inputs. The first approved Stable projection is sequence 1, authorized on 2026-10-20, binding RFEM 0.1.1 and Rhino 0.1.15 to their independently signed Windows assets. Both public ZIPs and receipts passed anonymous digest/length checks and production Host verification before formal discovery was updated. The signed `.agents/plugins/marketplace.snapshot.json` is the binding authority; this description is not a second identity catalog or a claim that every engineering tool was rerun for publication. Discovery points to `./published/<id>` relative to this repository root, in the same main Git tree; it never scans current development roots. Runtime and Yak assets remain outside Git history.

The independent Windows CI prepares only each selected project's own frozen environment. Present Connector projects run their package checks; absent projects are explicitly reported as `notPresent`, not as passes. The Rhino job builds and tests the native projects before Python integration tests. These are controlled component checks, not real Rhino engineering acceptance. Root checks verify exported contracts, artifact integrity, approved published views and signature scopes. Remote Actions results must be checked at the actual pushed commit; skipped live checks are not passes. The default manual candidate workflow validates/builds only; public Actions artifact uploads are restricted to synthetic fixture evidence. See [releasing.md](docs/releasing.md) for generator commands, signing inputs and final publication boundaries.

Never add credentials, private signing keys, business models, cache/runtime data or binaries to public source. See [AGENTS.md](AGENTS.md) for owner and verification boundaries.

Its independent builder stages a real locked Windows embedded CPython runtime and MCP declarations; it does not produce a signed release here. Startup version 2 metadata mode rejects calls; execution mode uses only isolated synthetic state. The fixture identity and test signer never enter Stable or production trust, and it provides no RFEM/Rhino readiness or engineering correctness evidence.
